Train the policy to use predicted target location

Live RGB → frozen Qwen ViT → visual features and predicted target-score map → trainable recurrent actor–critic → action → new RGB. Movement and stopping are learned through simulator rewards. No hand-written visual servo is called.

Goal-independent image proposals feed the existing frozen color/shape readout. Each region's conjunction score is rasterized into an 8×16 map. Maximum score and a no-proposal flag accompany it. No-proposal means perception uncertainty, not proof that the requested object is absent.

The map enters a learned projection, concatenated with visual attention, instruction embedding and previous action before the GRU. Policy, projection, GRU, actor and critic train; Qwen and the diagnostic readout stay frozen. The GRU can maintain history; the hand-written template memory is not used here.

Matched arms

  • zero: identical architecture, target signal replaced with zeros.
  • binding: predicted goal-conditioned spatial map.
  • shuffled: independently permuted map locations on each observation, preserving scores and summary descriptors. This tests the benefit of coherent spatial information, but does not alone prove a binding mechanism.

Same seeds, sampled training tasks, episode caps, reward, curriculum and action duration. Actual transition counts can differ when policies stop early. Initial and final greedy/sampled evaluations use matching original-start validation tasks and per-task action RNG seeds. Full runs: 96 training episodes per arm; 64 validation tasks in each action mode. Test geometries remain untouched. Existing readout split assignments are reused to avoid evaluating its training geometry as held-out.

Near-to-far training starts use privileged simulator setup. Evaluation starts remain original. Potential-based reward uses simulator distance; neither that distance nor object metadata enters the actor. This is not end-to-end label-free RL: the frozen readout was previously trained with simulator-derived color/shape labels. No new manual labels are required.

After smoke passes and logs are inspected, the three-seed development comparison is:

sbatch --array=0-8%2 scripts/slurm/binding_rl.sbatch full

Check initial-evaluation.json versus validation.json; report present arrival-and-stop and absent refusal separately. agent.pt records architecture and input mode; it is not interchangeable with old Agent checkpoints. Decisions record all 130 target-input values. Episode files retain actual movement GIFs and evaluator trajectories. No donor patches are included in this first RL comparison.

A positive result requires improvement over initialization and the zero-input policy across seeds. Failures may still arise from localization, exploration, insufficient training, or stopping. This implementation enables the test; it does not guarantee an improvement.
