Live image → selection → action → new image → stop

This runner executes new Minecraft episodes. Every action changes the next model input. It never replays teacher frames. A frozen Qwen visual encoder and existing color/shape readout select among image-derived regions. The new controller is hand-designed visual servoing, not a trained RL policy or general path planner.

Three paired arms

  • Recognition-only: current goal scores determine the selected region.
  • Recognition plus fallback memory: accepted recognition wins; a visual template can bridge low-score observations.
  • Old learned policy: seed 732, chunk 4 checkpoint, greedily evaluated on the same task list and original starts.

The old policy retains four-tick actions; visual servo arms use two-tick actions. Each has the same maximum simulation-tick budget, so this compares whole controllers, not a controlled architecture-only ablation. The recognition/memory pair has identical action duration and controller settings. A smoke run has one present and one absent task per arm; full evaluation has all four present goals across four families plus four absent tasks. These are development validation scenes; test scenes remain untouched.

What the controller can see

Only RGB and the structured goal. Candidate proposals use generic saturated-color connected components, with fixed HUD/hand exclusions. They do not use object coordinates, identity, ground-truth visibility or projected boxes. This is an arena-specific image-processing prior; it may merge, fragment, or miss objects. The existing readout was trained on privileged regions, so proposal distribution shift is a real failure risk.

The selected region's horizontal center determines left/right steering. When centered, the controller moves forward. A centered region at least 170 pixels tall triggers a stationary verification observation; a second qualifying observation triggers stop. This is a provisional apparent-size heuristic, not a depth estimate or guaranteed waypoint detector. It is explicitly recorded and has not been tuned on these evaluation results.

If recognition and memory both fail, the controller turns to search without moving forward. After 36 consecutive misses it stops with reason search_exhausted, not visual_arrival. World absence cannot be inferred merely from a failed detector. The existing evaluator requires immediate refusal for absent tasks, so a search-then-stop is scored as failure.

Scoring and evidence

Simulator state builds the scene and scores episodes only. Correct arrival requires stopping within 0.8 blocks of the same approach waypoint used previously. Save timeout, closest/final distance, entered-then-left, and stopped-at-wrong-waypoint metrics. Each episode saves actual movement, XYZ trajectory, decisions and selection-control GIF. The policy never receives evaluator coordinates.

No claim of improved navigation until these live results pass. The smoke gate tests execution, not learning. No manual review, new annotation, or teacher movement calls are required.
