From visual binding to action: causal interventions in an embodied agent

Executable stage 1: capture, baseline, head and strength experiments — Oscar commands

Main question: Which visual information controls object selection, when does it fail, and can preserving or correcting that information improve actual behavior?

Primary outcome: reliably reach the requested object under motion and occlusion. Secondary outcome: retain that success with fewer expensive model calls. Training and active exploration are explicit parts of this plan.

1. Test binding rather than color alone

Place a red pillar, blue pillar, red arch, and blue arch in the same scene. “Go to the blue arch” requires matching color and shape on the same object. Color alone leaves two candidates; shape alone also leaves two.

Balance every shape and color across positions. Add absent-target trials: a blue pillar and red arch do not imply a blue arch exists. Add three-dimensional depth, partial occlusion, and later relational goals such as “the arch behind the pillar,” as separately scored task families.

Matched counterfactuals: swap colors while preserving shapes and positions; separately swap shapes or positions. Preserve feature counts where possible. Compare conjunction judgments with color-only and shape-only judgments. Use four-object selection or a grounded region output plus “absent”; LEFT/RIGHT alone cannot identify four objects.

Gate: inspect rendered visibility and annotation alignment, then measure clean task competence on every case. Predeclare a development threshold (proposed 90% clean selection) before mechanistic screening. If it fails, improve the readout or train a selector first. Report all baseline failures; analyze patch effects on a separately labeled baseline-correct subset.

2. Explain V30/V31 more precisely

V30 means value-projection activations in the 31st vision block, using zero-based indices. The saved model has 32 vision blocks and 16 heads per block. Current patches replace all V channels at selected image tokens. A value vector is not automatically a “color neuron.” Q/K null results concern our tested intervention, images, and output metric; they do not show Q/K are unimportant.

3. Make the agent keep looking while moving

Observe

Current RGB + goal

Update memory

Object identity, estimated location, uncertainty, last seen

Choose

Approach, scan, reobserve, stop, or abstain

Execute briefly

Movement/camera actions → new observation

First use short action chunks and replan after each observation. Progress from camera turns to approach, then temporary occlusion, distractors and multiple rooms. Test whether the agent still follows the same requested object when it changes screen position.

Information boundary: primary agent receives RGB, the goal, action history and explicitly allowed proprioception. Ground-truth target coordinates and object IDs are evaluator/training labels only. Keep the existing privileged controller as a diagnostic upper-bound component; results using it must retain that label. Implement visually grounded bearing/waypoint estimation before claiming autonomous navigation.

Matched conditions: initial decision only; full-model refresh at every decision; fixed periodic refresh; memory with a learned refresh policy. Separately compare one-time vs repeated experimental patches. Align each new frame independently: a stationary screen rectangle is not the same object after a turn.

Recovery experiment: temporarily hide or degrade a feature, establish a real selection failure, then compare no repair, privileged clean-donor repair, and repair from the agent’s own earlier observation. Privileged repair diagnoses recoverable information; only the last condition is available to a deployed agent.

4. Training, search, exploration and exploitation

Yes, there should be training. First preserve frozen-model experiments as a causal reference. Then train a small useful component and test whether mechanistic knowledge improves it beyond ordinary learning.

LoRA provides one approach to train a limited set of added parameters while freezing pretrained weights. Fewer trainable parameters do not automatically mean cheaper forward inference.

Example of exploration versus exploitation: “I think the blue arch is behind this wall. Walking there exploits that belief. Turning to inspect the other opening gathers information that might prevent a wrong trip.” Train the choice using eventual correct arrival and observation cost, not merely confidence or novelty.

Distinguish three searches: offline mechanism search over heads/layers; online visual search for a target or informative viewpoint; and training-time action exploration to learn a policy. The second and third give this project its agent contribution. Broad Minecraft survival, mining and crafting would add many unrelated difficulties; start with multi-room target search.

Proposed reward: correct arrival − wrong arrival penalty − movement cost − expensive-observation cost. Tune costs on development episodes; publish separate success and cost metrics so a policy cannot look efficient simply by stopping early. Information-gain bonuses are optional ablations, not substitutes for task success.

5. Can memory reduce full-model calls?

Candidate design: store goal-relevant object features and location uncertainty. A cheap tracker/memory policy handles short motion segments and requests a fresh full-model observation when identity is ambiguous, the view changes substantially, or the object disappears. Compare causal-site features with generic embeddings; do not assume V30 is the best memory representation.

Cache reuse has relevant prior work, including VLA-Cache. Our proposed differentiator is testing which task-relevant object information must survive and whether that knowledge improves the success–compute tradeoff. Novelty requires a fuller literature comparison before making a paper claim.

Count all costs: full model, visual encoder, tracker, memory, token count, GPU-seconds and wall-clock latency. Reusing decoder work while still running the full vision encoder is different from skipping a full-model call. Compare at matched task success and matched action/observation budgets.

Evaluation and stopping rules

  • Primary: correct conjunction-target arrival within a fixed episode budget, measured from simulator state by the evaluator. Also report wrong-object arrivals, abstentions, path efficiency, reacquisition after occlusion, and object-identity switches.
  • Split by scene family: keep every counterfactual, frame, reversed color assignment and trajectory from a layout in one split. Reserve new layout/viewpoint families for final testing. Select heads, prompts, α values and policies only on training/development data.
  • Starting allocation, not a power calculation: 24 development/debug layouts, then approximately 120 training, 40 validation and 80 untouched test layouts, with balanced goals and counterfactual pairs. Adjust sample size using development variance before opening the final test. Existing 24 configurations remain exploratory evidence.
  • Uncertainty: report per-family results and confidence intervals clustered by layout; trained-policy experiments start with three seeds. Repeated layers and two sides are not new independent scenes.
  • Efficiency success criterion: predeclare an acceptable accuracy loss (suggested at most 2 percentage points) and show its confidence interval alongside compute savings. If precision is insufficient, collect more independent episodes rather than claim equivalence.
  • Gates: capture alignment → clean competence → self-patch identity → causal specificity → closed-loop logging → natural-failure rescue → efficiency. Failed gates remain reported results and determine the next engineering step.

Visual evidence for every moving trial

Save a synchronized raw-HUD video/GIF, XYZ/yaw trajectory and timeline. At each decision show: exact input frame, goal, candidate objects, chosen object, confidence, model-call event and executed actions. Mark exact intervention token locations only when a patch occurred. Use separate labels for evaluator annotations, tracker estimates, and actual intervention masks. A video overlay is not proof that the model attended to those pixels.

Report paired clean/patched/repaired episodes with identical starting states and environment seeds. Show failures alongside successes. Include plots of arrival rate versus model calls, reacquisition delay after occlusion, and head/strength effects with uncertainty.

Concrete implementation order

  1. Binding task: add balanced four-object scene generation, grounded four-way/absent readout, capture review and clean baselines. Deliver a screenshot-based report with feature-confusion counts.
  2. Mechanism pilot: implement verified head slicing and α interpolation; run the 32 single-head sites across V30/V31 on development cases. Add reverse/ablation/rescue controls before expanding searches.
  3. Closed-loop baseline: connect current observations to new target decisions during short movement chunks, then replace privileged target localization. Deliver synchronized decisions, raw frames and trajectories.
  4. Train memory and sensing: learn target grounding/memory first; add observation scheduling and active viewpoint choice. Compare ordinary versus mechanism-informed features under identical budgets.
  5. Freeze and evaluate: test held-out scenes, occlusion and paraphrases; extend to a second model only after the primary effect and behavioral measurement are stable.

Before each expansion, benchmark a small run and estimate forward passes, storage and GPU time. Cache reusable clean/donor values and checkpoint each case. Cap exploratory head combinations rather than launching an unbounded combinatorial search. This document authorizes no training jobs and reports no new experimental successes.

Intended contribution: an experimentally grounded account of object selection, plus an agent that demonstrably preserves the right target and knows when another look is worth its cost. If causal-site guidance does not outperform generic features, report that outcome rather than force a mechanism-based policy claim.
