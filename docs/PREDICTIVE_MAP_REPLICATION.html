Predictive coding cognitive-map replication

The reference is Gornet & Thomson, Automated construction of cognitive maps with visual predictive coding. Its official implementation is the reference subject. Keep its supplied notebooks and experiment workup intact. Do not run notebook installation cells. This project adds an external runner; it does not retrain or alter the author's model.

Order and claims

  1. Reference first. Check the official source revision and released data; run the predictive checkpoint on the saved environment, path, and circular-corridor arrays. Record next-image MSE, a position readout, and latent-versus-physical distances. The circular plot uses a 30-unit wrapped coordinate, as in the released analysis. Compare the plots and numbers to the paper before calling this a reproduction. The released saved arrays are not documented as independently routed held-out evaluation data. Their notebook also trains and evaluates the published position decoder on the same saved latents. Our ridge readout uses an 80/20 sequence-order split, but neighboring sequences may still leak route/scene information. Label both analyses descriptive.
  2. Frozen V-JEPA second. Use the same new Minecraft sequences for video and the repeated-last-frame control. Do not give either encoder coordinates, route IDs, or headings. Fit a position readout only on training trajectories; evaluate on independently routed held-out trajectories from the same world. Plot pairwise latent distance against world distance, conditioning on heading/view and temporal separation. Compare video and repeated-frame activations at the same layers. V-JEPA is a video representation model, not the reference's image-prediction decoder; next-image pixel MSE is not directly available from the frozen encoder.
  3. Eight worlds third. Apply the locked analysis and criteria to the diverse-v2 environments after steps 1–2. Existing 16 routes / 188 extracted clips are useful for a pipeline audit, but too sparse for strong place-field, gridness, or distance-geometry claims.

This tests spatial coding and spatial relationships. A latent-distance correlation alone is not a demonstrated cognitive map or grid/place cell. Route and view invariance, enough 2D coverage, and appropriate controls are required. Do not report gridness for a corridor.

The released environment image array has 1,536 sequences of 10 frames, although the notebook constructs a model with seq_len=20. The reference attention code accepts the actual sequence length. The runner now records and checks the array shape during preflight instead of imposing 20 frames on saved data. Oscar job 8012190 stopped at this previously incorrect shape check; it produced no model result.

Scale audit before spatial claims. Job 8020991 ran the official checkpoint and released environment array unchanged, but a sample across the array revealed that inverse-normalized RGB peaks at about 1/255. Multiplying those values by 255 recovers visible Minecraft scenes. The original image comparison was blue because it displayed normalized channels with one shared percentile scale. Its next-image MSE of 0.0216 is therefore not a reliable reproduction of the paper's visual-prediction result. The released asset's SHA256 matched the downloaded file; the exact stage that introduced the extra scaling is unverified. The ridge decoder's 80/20 sequence-order split and random global distance pairs also differ from the paper's in-sample neural decoder and local path distances.

The runner now offers a separately labeled diagnostic transform for the environment case. It leaves the official .npy and checkpoint untouched, checks the suspected scale, reverses the extra factor of 255 in memory, and reports both model MSE and copy-previous-frame MSE. It renders actual and predicted images in RGB. Run this before any paper decoder, path, circle, or V-JEPA comparison:

cd ~/projects/zef-binding

Corrected-scale audit result (Oscar 8028057). The released file remained unchanged; the in-memory correction produced recognizable Minecraft images and a blurred but scene-aligned next-image prediction. Across the saved environment sequences, next-image MSE was 0.10230, while copying the previous frame gave 0.08244 (lower is better). Thus the checkpoint did not beat this simple temporal baseline on these arrays. The ridge readout's sequence-order split improved from 31.83 to 20.98 lattice units, against a train-mean baseline of 32.95, but its train/test geography differs and it is not the paper's decoder. Random global-pair latent/physical Spearman was 0.237, not the paper's local-path analysis. The paper's reported image MSE of 0.094 uses its published setup and is not yet matched by this audit. Before a reproduction claim, verify the correction against original RGB frames and evaluate the reference readout and local-path protocol; do not infer place/grid cells or a cognitive map from these numbers alone.

Original-PNG and pixel-scale checks. The authors' repository tracks 82,630 validation PNGs. One original ten-frame episode was checked directly from Git: its RGB values span 0 to 0.996 after ordinary division by 255. It did not match any of the first 16 sequences in the released environment array after our proposed scale restoration (RGB MSE 0.093 to 0.227); the released array may contain a different subset or order. A separate check of released sequences 0, 384, 768, 1152, and 1535 found that inverse normalization followed by multiplication by 255² produces values within 0.0051 of 8-bit integer channel levels, with ranges such as 4–255 and 2–255. Together with the inverse-normalized maximum of 1/255, this is strong evidence of an extra division by 255 in the saved array. It does not identify which preprocessing step introduced it, or establish that our restored-scale model scores reproduce the authors' evaluation. We have not identified an original episode corresponding to a released sequence; keep those scores labeled diagnostic.

Dense single-world Minecraft gate

Before V-JEPA map claims, collect a separately versioned world with an open, two-dimensional traversable area and two distant sites deliberately made visually similar. Keep the diverse-v2 source untouched. Record continuous RGB, actual XYZ and yaw, actions, collision/stuck checks, camera and tick timing, route IDs, world build/seed, and raw PNG hashes. Use several independent routes per site with opposite headings and at least one visually ambiguous pair. Require occupancy across the open area, same-location revisits from different headings, and near/far pairs at matched headings; show these counts before fitting a probe. Train/readout on whole trajectories and hold out whole trajectories, never random clips. No new architecture or learned memory is added to frozen V-JEPA.

The current scripted routes and rendering system can be reused as components, but this denser collection has not been run or validated. Real Minecraft rendering and the frozen model forward pass remain explicit gates. Synthetic unit tests are labeled non-Minecraft and do not satisfy either gate.
