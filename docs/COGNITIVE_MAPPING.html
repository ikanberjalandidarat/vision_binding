Learning spatial relationships from movement and visual experience

Hippocampal-inspired associative memory in Minecraft. Candidate g/p populations; self-supervised sensory prediction with privileged odometry.

1. What we built

The g state is movement-conditioned; visual prediction loss trains its weights. The p layer combines g with retrieved features. These are an inspired prototype, not an exact TEM/TEM-t reproduction. Simulator coordinates drive scripted collection and score activity; absolute coordinates do not enter the memory forward pass.

3. New experiment: same place, different histories

Four loops intersect at a common anchor. Every loop returns there and records headings 0°, 90°, 180°, −90°. Each route contains two rounds and 36 heading probes. Routes 0/1 use different loop orders for training. Routes 2/3 reverse traversal and use held-out orders. All routes share the same reset procedure and anchor.

  • Pilot: six distinct geometries, four routes each. Four training geometries, one validation, one test.
  • Training uses only routes 0/1 in training geometries, with a sensory-prediction objective.
  • Fixed ridge location readouts train only on frozen training representations. Coordinate supervision belongs to this evaluator, not the memory.
  • Compare learned g/p to untrained g/p and a time/heading baseline. Measure same-heading loop-return changes and actual endpoint mismatch.
  • Incomplete collection stops before training. Check actual probe coverage and route completion before interpreting results.

Heading probes cover one anchor, not the entire arena. This tests a specific source of confounding; it is not a full grid-cell experiment. One model seed is a pilot, not a replicated result. A good location readout alone does not establish hexagonal grid periodicity.

4. Run on Oscar

After the user commits/pushes the changes, pull them on Oscar. No local checkpoints or downloaded pilot files need uploading for this fresh run.

cd ~/projects/zef-binding
git pull
mkdir -p logs
smoke_job=$(sbatch --parsable scripts/slurm/cognitive_mapping.sbatch smoke 731)
sbatch --dependency=afterok:"$smoke_job" --kill-on-invalid-dep=yes \
  scripts/slurm/cognitive_mapping.sbatch pilot 731

Smoke performs complete routes in three geometries with only three fitting epochs. It checks execution, not learning. Pilot trains for 100 epochs. Both use the existing model/render environments; real Minecraft and GPU execution remain unverified until these jobs finish. Queue/runtime cannot be guaranteed for tomorrow.

Outputs: /oscar/scratch/$USER/zef-binding/runs/cognitive-mapping-JOBID/. Inspect status.json, review.json and cognitive-review.json first. Download those small JSONs before selecting GIFs. The presentation report is analysis/cognitive-map.html; every embedded GIF has its source path below it.

5. Suggested presentation wording

“We are testing whether movement-conditioned associative memory learns reusable spatial relationships from Minecraft visual experience. The current pilot shows useful retrieval, but does not yet establish stable allocentric place/grid coding. Our next controlled experiment revisits the same location under different routes and headings and measures spatial information in frozen representations.”

Show the existing GIF as a visualization of measured candidate activity. Label any new results pending until the run completes. Successful rendering, sensory prediction, spatial generalization and biological cell-like tuning are separate claims.
