Next study: can it select, start, and arrive reliably?

Presentation-ready movement / attention / Grad-CAM gallery · Previous 2×2 experiment

The previous run reached 13/56 present validation targets with raw images and timestep weighting. It did not establish reliable navigation or a binding mechanism. This study adds repeated seeds, stricter scoring, startup/turn-focused training, and an independent object-selection task while keeping the current data fixed.

All policies use cached raw visual features from the same frozen Qwen vision encoder. The new selector uses the same visual/language attention backbone with a five-way output at startup; it is trained independently and does not control navigation in this study. Known boxes/order define labels only, never policy inputs. In three-object absent scenes, region labels refer to the visible left-to-right order; choosing a nonexistent fourth region is an error.

Navigation loss retains per-timestep weighting. The focused arm additionally weights the first decision ×5 and each turn label ×2 (a starting turn receives ×10). This is a predeclared combined treatment; it does not separately isolate startup and turn weighting. Both arms retain the same optimizer, clipping, architecture, demonstrations and epoch budget. Checkpoints use validation loss under the declared training objective. The focused objective can still hurt stopping or arrival; no improvement is assumed.

Splits, seeds and claims

The split seed stays 731 for every run, while initialization/training-order seed varies. Color-swap contexts and related configurations remain in one geometry split. All 64 validation episodes are requested for each policy (56 present, 8 absent). No new held-out test metrics are produced by this study. The original test results already informed debugging, so a final claim should eventually use fresh held-out scenes.

Three seeds measure optimization variability, not generalization to new worlds. The current dataset still has only six geometry groups, one arena and red/blue arch/pillar combinations. Do not treat repeated episodes or seed repetitions as independent Minecraft environments. Present per-seed results and failure modes before averaging.

Scoring version navigation_v2

  • Present target: STOP within 0.8 blocks of the correct approach waypoint.
  • Absent target: STOP immediately, before any movement/turn action. This is the explicit abstention task for this arena; exploration tasks would need a different rule.
  • Record path distance, maximum displacement, nearest sampled distance to goal, timeout and immediate false stop.
  • Keep legacy_success for comparison. Old run files are never rewritten; the gallery's episode-analysis.json retrospectively applies the new definition.

The simulator worker now rejects error/fallback observations and prints its full traceback. This improves diagnosis of connection failures, not simulator reliability itself. Simulator errors remain failed runs rather than navigation failures.

How this leads to a mechanism experiment

  1. Establish clean conjunction selection and actual arrival under stricter metrics across seeds.
  2. If selection works but movement fails, collect teacher corrections on policy-generated trajectories in training scenes only; then compare behavior cloning with those corrections. This on-policy collector is not implemented in this suite.
  3. If selection fails, use the startup selector and known-region diagnostic readouts to separate color, shape and location errors. No-image/word ablations are input-dependence probes, not proof of a ViT circuit.
  4. Once a clean selection baseline is reliable, patch or ablate V30/V31 heads and compare donor, self, random and reverse interventions. Measure region-score and action changes with visual alignment verified on new frames. These closed-loop head interventions are not implemented here.
  5. Freeze a revision, then evaluate new geometry, camera views, colors and shapes, including motion/occlusion and failure recovery.

Fewer model calls, reinforcement learning rewards, obstacle navigation and general Minecraft play remain separate research goals. This implementation does not claim those outcomes.
